# AI Practice — домашние задания курса

Репозиторий с домашними заданиями курса по AI-инженерии. Каждое задание живёт в своей папке.

| Папка | Задание |
|---|---|
| [`day1/`](day1/) | Запрос к LLM через API: чат в консоли и в веб-интерфейсе (Gradio) |
| [`day2/`](day2/) | Управление ответом модели: формат, длина, условие завершения |
| [`lab/`](lab/) | Чат-лаборатория: ограничители дня 2 (формат, длина, условие завершения) на любое сообщение диалога — промптом или параметром API |
| [`day3/`](day3/) | Разные способы рассуждения: одна задача решается через API четырьмя способами (+2 доп. эксперимента), сравнение ответов с эталоном |
| [`day4/`](day4/) | Температура: один запрос на нескольких значениях температуры, сравнение точности, креативности и разнообразия |
| [`day5/`](day5/) | Версии моделей: слабая / средняя / сильная — время, токены, стоимость и слепая оценка качества |
| [`day6/`](day6/) | Первый агент: класс `Agent` с личностью и памятью диалога на сервере + веб-чат |
| [`day7/`](day7/) | Сохранение контекста: история диалогов агента в SQLite, восстановление после перезапуска сервера |
| [`day8/`](day8/) | Токены: подсчёт запроса/истории/ответа, рост стоимости по ходам, лимит контекста и поведение при переполнении |
| [`day9/`](day9/) | Управление контекстом: последние 10 сообщений как есть, старые — в summary (скользящее или по чанкам), карта контекста и расход токенов по режимам |
| [`day10/`](day10/) | Стратегии контекста без summary: sliding window, sticky facts (ключ: значение), branching (чекпойнт → две ветки) — сравнение на одном сценарии |
| [`day11/`](day11/) | Модель памяти агента: три слоя в разных хранилищах — краткосрочная (транскрипт), рабочая (карточка задачи на область чатов), долговременная (файл) |
| [`day12/`](day12/) | Персонализация ассистента: профили пользователя в markdown-файлах, привязка к чату и инъекция в каждый запрос, опциональный пайплайн ответа |

API — Z.ai и DeepSeek (оба совместимы с OpenAI SDK; ключи в `.env` в корне репозитория, не коммитятся — шаблон: `.env.example`). Модели: `glm-5.3` в day1, `glm-4.6` (по умолчанию) и `glm-5.3` в day2, lab и day3–day5 (в day5 ещё бесплатный `glm-4.5-flash`); в day6–day12 агент по умолчанию говорит на `deepseek-v4-flash`, `glm-*` — опционально.

## Установка

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env
# впишите свой ключ в .env: GLM_API_KEY=ваш-ключ
```

Подробности по каждому заданию — в README внутри его папки.

## Новые задания — через OpenSpec

Репозиторий переведён на spec-driven workflow (`openspec/`): одно задание =
один change (`proposal.md` → `design.md` → `tasks.md` → дельты спек),
архив `openspec/changes/archive/YYYY-MM-DD-*` — это запись дня. Спеки
(`openspec/specs/`) описывают текущее состояние того, что ещё развивается;
завершённые дни 1–10 задним числом не специфицируются. Правила работы для
агентов — в `AGENTS.md`.
