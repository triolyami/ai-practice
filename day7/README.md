# Сохранение контекста — день 7

Задание: добавить агенту сохранение контекста — хранить историю диалога
(messages) в JSON или SQLite, при перезапуске загружать её обратно и
продолжать диалог так, как будто агент не выключался. Проверка на практике:
начать диалог → перезапустить приложение → продолжить диалог и убедиться,
что агент помнит прошлые сообщения.

## Что изменилось со дня 6

В день 6 память агента (`Agent.history`) жила только в экземпляре класса:
перезагрузка страницы переживалась запросом `GET /api/agent`, но перезапуск
сервера стирал всё — `REGISTRY` пуст, и чат из сайдбара начинал жизнь с нуля.
День 7 добавляет под агентами третий слой — **диск**: каждый завершённый
ответ агента сохраняется в SQLite, а при обращении к сессии, которой нет в
памяти, агент бесшовно восстанавливается из базы.

```
браузер (React) ──POST /api/chat──▶ server.py ──▶ Agent.send_stream()
                                        │              │        ▲
                                        │   ответ готов │        │
                                        ▼              ▼        │
                                    storage.ChatStore ──▶ snapshot/history
                                     day7/data/chat_history.db
```

- **`storage.py`** (новый) — `ChatStore`: единственный, кто знает про SQL.
  Две таблицы: `sessions` (личность агента: имя, модель, системный промпт,
  признак «промпт по умолчанию») и `messages` (реплики по порядку: роль,
  текст, JSON с метаданными ответа). Соединение открывается на каждую
  операцию (сервер многопоточный), журнал WAL, запись — одной транзакцией:
  апсерт сессии + полная замена её реплик.
- **`agent.py`** — два метода для сохранения/восстановления: `snapshot()`
  (как `describe()`, плюс `_default_prompt`, чтобы после восстановления
  смена имени по-прежнему пересобирала дефолтный промпт) и класс-метод
  `from_snapshot()` (собирает агента из снапшота, выкидывая битые записи и
  обрезая историю до того же окна в 20 реплик). Логика диалога не изменилась.
- **`server.py`** — `resolve_agent()`: сначала реестр в памяти, при промахе —
  база. Сюда завязаны `GET /api/agent` (транскрипт для страницы),
  `POST /api/chat` (сама модель помнит прошлые реплики) и `POST /api/reset`.
  Сохранение — после каждого `done`: ответ дошёл до конца → снапшот агента в
  базу; оборванный генерацией или ошибкой ход не сохраняется.

## Семантика

- **Сохраняется**: история диалога (до 20 реплик — то же окно, что видит
  модель) и личность агента (имя, модель, системный промпт). Метаданные
  ответов (модель, токены, латентность) едут вместе с репликами.
- **Перезапуск сервера** теперь не заметен: сайдбар берёт чаты из
  localStorage браузера, клик по чату подтягивает транскрипт из базы через
  `GET /api/agent`, следующее сообщение уходит в контексте всей прошлой
  истории.
- **«Сбросить диалог»** (`POST /api/reset`) чистит память агента **и** его
  строку в базе — иначе «забытый» диалог воскрес бы после перезапуска.
- **«Удалить чат»** (`POST /api/forget`) удаляет агента и из реестра, и из
  базы. Вытеснение из LRU (лимит 16 агентов в памяти) базу не трогает —
  вытесненный агент возвращается из базы при следующем сообщении.
- Битые записи при загрузке отбрасываются, превышение окна — обрезается:
  база не может «отравить» агента.

## Запуск

Фронтенд собран и закоммичен в `day7/frontend/dist/`, поэтому Node не нужен:

```bash
cp .env.example .env   # вписать GLM_API_KEY и/или DEEPSEEK_API_KEY
.venv/bin/python day7/server.py
```

Открыть <http://127.0.0.1:7866>. При старте сервер печатает путь к базе и
число сохранённых чатов. Модели и ключи — те же, что в дне 6.

Проверка сценария дня 7 вручную:

```bash
.venv/bin/python day7/server.py &          # 1. старт
curl -sN -X POST http://127.0.0.1:7866/api/chat -H 'Content-Type: application/json' \
  -d '{"session_id":"demo7","message":"Меня зовут Толик. Запомни моё имя."}'
kill %1                                    # 2. перезапуск
.venv/bin/python day7/server.py &
curl -s "http://127.0.0.1:7866/api/agent?session_id=demo7"   # 3. exists:true, транскрипт на месте
curl -sN -X POST http://127.0.0.1:7866/api/chat -H 'Content-Type: application/json' \
  -d '{"session_id":"demo7","message":"Как меня зовут?"}'    # 4. в ответе — «Толик»
```

Заглянуть в базу без сервера:

```bash
.venv/bin/python -c "import sqlite3; conn = sqlite3.connect('day7/data/chat_history.db'); \
print(conn.execute('SELECT session_id, name, model FROM sessions').fetchall())"
```
