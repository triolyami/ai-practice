# День 2 — управление ответом модели через API

## Задание

Отправьте один и тот же запрос, но:
👉 добавьте явное описание формата ответа
👉 добавьте ограничение на длину ответа
👉 добавьте условие завершения ответа (stop sequence или явную инструкцию)

Сравните ответы:
👉 без ограничений
👉 с ограничениями

Результат: один и тот же запрос с разным уровнем контроля ответа через API.

## Как выполнено

Базовый промпт — «Расскажи, как устроен интернет» — отправлен 7 раз. Во всех прогонах
одинаковые условия: `temperature=0`, `thinking: disabled`. Меняется только механизм контроля:
в паре «промпт» ограничение сформулировано словами в запросе, в паре «API» — параметром запроса.

| # | id | Что добавлено | Механизм |
|---|---|---|---|
| 1 | baseline | ничего | — |
| 2 | format-prompt | описание JSON-формата словами | промпт |
| 3 | format-api | то же + `response_format={"type":"json_object"}` | API |
| 4 | length-prompt | «Ответь не более чем 30 словами.» | промпт |
| 5 | length-api | `max_tokens=60` | API |
| 6 | stop-prompt | «Заверши ответ после первого абзаца…» | промпт |
| 7 | stop-api | `stop=["\n\n"]` | API |

Каждый прогон сохраняет полный ответ, `finish_reason`, `usage` и метрики
(слова, абзацы, валидность JSON) в `results.json`. Страница `index.html`
собирается из `template.html` с этими данными — она самодостаточна и
открывается в браузере двойным кликом, без сервера и без API-ключа.

## Почему glm-4.6, а не glm-5.3

Первые прогоны делались на glm-5.3 (модель из day1). Оказалось, что она «всегда думает»:
отключить reasoning нельзя (API предлагает только уровни low/high/max), а токены скрытых
рассуждений идут в общий счёт. Из-за этого `max_tokens=60` целиком съедался рассуждениями
(видимый ответ — пустой), а `stop=["\n\n"]` срабатывал внутри рассуждений до начала ответа.
Итоговая матрица выполнена на glm-4.6 с `thinking: disabled` — там ограничения действуют
именно на видимый текст. История с glm-5.3 оставлена на странице как отдельная находка.

## Запуск

```bash
cp .env.example .env   # и вписать свой GLM_API_KEY
../.venv/bin/python experiment.py                 # 7 новых прогонов + сборка страницы
../.venv/bin/python experiment.py --render-only   # пересобрать страницу из готового results.json
```

(из папки `day2/`; либо из корня: `.venv/bin/python day2/experiment.py`)

## Выводы

1. **Параметры API — гарантии, промпт — просьба.** В этой серии модель была послушна
   и выполнила все три промпт-инструкции (23 слова из 30, один абзац, валидный JSON),
   но каждое выполнение — её собственное решение. API-механизмы работают физически:
   ровно 60 токенов с обрывом на полуслове, срез ровно на первом `\n\n`, всегда
   парсируемый JSON.
2. **`finish_reason` — единственный свидетель усечения**, и то не всегда: обрезку по
   `max_tokens` он помечает как `length`, а вот stop-обрыв приходит как обычный `stop` —
   со стороны API неотличим от естественного завершения.
3. **Лимит в токенах не равен лимиту в словах**: 60 токенов — это 36 русских слов,
   больше, чем 30, о которых просили в промпте.
4. **JSON-режим Z.ai** — только `json_object` (`json_schema` не поддерживается): API
   гарантирует валидность, но схему полей по-прежнему описывает промпт.
