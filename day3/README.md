# День 3 — реши одну задачу несколькими способами

Одна логическая задача решается через API агентами: в панели слева —
библиотека агентов (имя, инструкция, модель) и два пайплайна; в карточке
задачи отмечается, кого запускать, — и ровно столько карточек с решениями
появляется ниже. Четыре агента встроены по заданию и идут как список
по умолчанию, любого можно отредактировать. Внизу страницы — сравнение
финальных ответов с эталоном и вердикт жюри: кнопка «оценить ответы»
собирает все отмеченные завершённые прогоны в один запрос к glm-5.3,
который ранжирует их по трём критериям — правильность, обоснованность,
ясность. Замороженный прогон коммитится в
`results.json` и открывается на странице сразу, без API-ключа; кнопку
«начать свой прогон» можно запустить всё заново на встроенной или своей
задаче. Новый запуск («запустить» или «перезапустить» у карточки)
сбрасывает вердикт жюри — тот описывал ответы прошлых прогонов.

## Задача и эталон

`puzzle.py` — логическая задача: кто из четырёх коллег в каком городе
живёт и сколько ему лет (6 условий, города и возрасты без повторов).
Эталонный ответ единственный, это подтверждено полным перебором всех
комбинаций в `verify.py`:

```bash
.venv/bin/python day3/verify.py
```

Пока задача встроенная, страница автоматически сверяет каждый ответ с
эталоном (бейдж «совпало / не совпало» на карточке и колонка в таблице).
Свою задачу можно вписать в карточку задачи — тогда сверка отключается.

## Агенты

Агент — это имя, инструкция и модель; запуск — ровно один запрос:
непустая инструкция ставится перед задачей, пустая — модель получает
просто задачу. Встроенные агенты (список по умолчанию, редактируется
в панели слева):

1. **Прямой ответ** — без инструкции, `glm-4.6`.
2. **Пошагово** — инструкция «Решай пошагово.», `glm-4.6`.
3. **Группа экспертов** — одной инструкцией просит аналитика,
   инженера и критика решить задачу в одном запросе, `glm-4.6`.
4. **Нативное рассуждение** — без инструкции, но на `glm-5.3`
   (effort low): проверка, что даёт встроенное мышление модели.

У каждого агента выбирается effort — low, high или max; он действует
на моделях, которые всегда думают сами: `glm-5.3` и `glm-5.3-flash`
(у них API отвергает отключение thinking). У `glm-4.6` thinking нет,
поэтому поле effort там скрыто. Обе модели DeepSeek — `deepseek-v4-flash`
и `deepseek-v4-pro` — тоже рассуждают сами, без настройки усилия.
По умолчанию — low.

Полный список моделей: `glm-4.6` (no reasoning), `glm-5.3`,
`glm-5.3-flash` (Z.ai, общий ключ), `deepseek-v4-flash` и
`deepseek-v4-pro` (DeepSeek). Для DeepSeek впишите свой ключ в файл
`.env` в корне репозитория — строкой `DEEPSEEK_API_KEY=sk-...` рядом с
`GLM_API_KEY` (шаблон — в `.env.example`) — и перезапустите сервер; без
ключа выбор такой модели вернёт понятную ошибку, остальные работают.

Своих агентов можно добавлять кнопкой «+ агент», у каждого — своя
инструкция и модель. Ниже, в блоке «пайплайны», живут два
многошаговых пайплайна — «сначала промпт» (модель пишет промпт,
затем решает по нему) и «эксперты по очереди» (отдельный запрос
аналитику, инженеру и критику, затем синтез). Шаги и порядок
фиксированные, но инструкцию каждого шага можно править; все шаги —
на `glm-4.6`. Промежуточные шаги раскрываются в карточке, итог
пайплайна — ответ последнего шага. В каждой карточке раскрывается
«что ушло в модель» с фактическим текстом запроса.

## Итоги замороженного прогона (2026-09-06)

Строки «сначала промпт» и «эксперты по очереди» получены старым
прогоном; сами пайплайны в приложении есть и сейчас — правятся в
панели слева.

| Способ | Верно | Токены (completion) | Время |
|---|---|---|---|
| Прямой ответ | да | 523 | 8.3 с |
| Пошагово | да | 566 | 7.7 с |
| Сначала промпт | **нет** | 306 | 7.3 с |
| Группа экспертов (1 запрос) | да | 1297 | 15.0 с |
| Эксперты по очереди + синтез | да | 5282 | 67.9 с |
| Нативное рассуждение (glm-5.3) | да | 1061 | 16.9 с |

- **Ответы отличаются.** Пять способов из шести дали верное решение, но с
  разной формой подачи; «сначала промпт» ошибся в возрастах (города при
  этом назвал верные).
- **Самая показательная неудача — «сначала промпт».** Модель написала
  вполне разумный промпт (таблица, метод исключения, проверка
  противоречий), но в последнем пункте попросила «выдать ответ без
  промежуточных рассуждений» — и, послушно пропустив рассуждение,
  ошиблась. Качество сгенерированного промпта не гарантируется: стратегия
  добавляет лишнее звено, которое может работать против задачи.
- **«Решай пошагово» почти ничего не меняет**: glm-4.6 и без инструкции
  отвечает пошагово — baseline сам построил ту же цепочку. Инструкция
  повлияла только на оформление (пронумерованные шаги).
- **Эксперты: один запрос эффективнее четырёх.** Оба варианта решили
  верно, но мультиагентный потратил в ~4 раза больше токенов и времени;
  зато синтез действительно проверил решения и отбил мелкие оговорки
  экспертов (на тестовой задаче при отладке он даже исправил ошибку
  «критика»).
- **Нативное рассуждение не спасает от необходимости проверять**: glm-5.3
  решил верно и аккуратно самопроверился, но и стоил это дороже прямого
  ответа. Промптовые техники на модели с выключенным thinking остались
  конкурентоспособны.
- Оговорка: это один прогон с temperature 0; на более сложной задаче разрыв
  между способами был бы заметнее — современная модель решает такие задачи
  уверенно даже без подсказок.

## Запуск

Фронтенд — React (Vite), собранные файлы коммитятся в
`day3/frontend/dist/`, поэтому для работы страницы Node не нужен:

```bash
cp .env.example .env   # и вписать свой GLM_API_KEY, если ещё нет
.venv/bin/python day3/server.py
```

Открыть <http://127.0.0.1:7862> (в WSL2 — по eth0-IP: `0.0.0.0` уже
прописан). Сервер — стандартная библиотека Python + `openai`, ключ берётся
из `.env` в корне репозитория. Маршруты: `/` — страница, `/results.json` —
замороженный прогон, `POST /api/solve` — решение агентом (тело
`{task, agent: {id, name, instruction, model, effort}}`) или пайплайном
(тело `{task, pipeline: {id, instructions, model}}`); ответ — NDJSON-поток
`start` → `delta`… → `done`. `POST /api/judge` — вердикт жюри (тело
`{task, answers: [{id, name, text}]}`, ответ — JSON
`{judge: {ranking, best, verdict}, meta}`). До 6 запросов идут
параллельно — общий пул слотов на `/api/solve` и `/api/judge` (409,
когда все заняты), «стоп» обрывает все текущие генерации.

Пересоздать замороженный прогон:

```bash
.venv/bin/python day3/run_all.py   # 6 реальных запросов к API → results.json
```

## Пересборка фронтенда

Нужен Node 20.19+ / 22.12+ (здесь — тарболл в `~/.local/opt`, симлинки в
`~/.local/bin`):

```bash
cd day3/frontend
npm install        # один раз
npm run build      # соберёт dist/, сервер отдаёт его как есть
npm run dev        # режим разработки: :5174 с прокси /api и /results.json на :7862
```

Прогон страницы живёт в localStorage браузера (`day3-runs-v1`); замороженный
прогон подгружается с `/results.json`, только пока своего прогона нет.
