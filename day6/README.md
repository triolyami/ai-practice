# Первый агент — день 6

Задание: реализовать агента, который принимает запрос пользователя, отправляет
его в LLM через API, получает ответ и выводит результат в интерфейсе. Ключевое
требование — агент должен быть **отдельной сущностью**, а логика запроса и
ответа — инкапсулирована в нём, а не размазана по коду интерфейса.

## Где жил «агент» до этого дня

В `lab/` (чат-лаборатория дня 2) «агент» уже почти был — но разрезан надвое:
память диалога хранилась в браузере (`App.jsx` собирал всю историю и слал её
на сервер с каждым запросом, localStorage — единственное хранилище), а вызовы
LLM жили на сервере (`server.py`, stateless — он ничего не помнил между
запросами). Мозг был в JavaScript, рот — в Python, и ни одной сущности,
которая владеет тем и другим, не существовало. День 6 склеивает эти половины
в один класс.

## Архитектура

```
браузер (React)  ──POST /api/chat {session_id, message}──▶  server.py  ──▶  Agent.send_stream()
   тонкий клиент          ◄── NDJSON: start/delta/done ──▶  (транспорт)        (вся логика)
                                                                                  │
                                                                  LLM API (OpenAI SDK): Z.ai / DeepSeek
```

- **`agent.py`** — сущность. Класс `Agent` владеет личностью (имя + системный
  промпт), памятью (история диалога) и параметрами модели, и сам делает весь
  цикл «запрос → LLM → ответ». Не знает ни про HTTP, ни про браузер: работает
  и без всякого сервера —

  ```bash
  cd day6 && ../.venv/bin/python -c "from agent import Agent; print(Agent().send('привет'))"
  ```

- **`server.py`** — только транспорт: сопоставляет `session_id ↔ экземпляр
  агента` (у каждого чата в сайдбаре — свой агент со своей памятью), гонит
  события агента в NDJSON-стрим, раздаёт собранный фронтенд. Про LLM сам не
  умеет ничего.
- **`frontend/`** — «глупый терминал» на React (скелет из `lab/frontend`):
  шлёт только `{session_id, message, config}`, историю не хранит. Панель
  настроек агента — имя, системный промпт, модель — сворачивается и
  разворачивается чипом «агент: …» над полем ввода (по умолчанию спрятана,
  выбор запоминается); применяется к экземпляру на сервере сразу, память
  диалога при этом сохраняется.

### Класс `Agent`

```python
agent = Agent(name="Барсик", system_prompt="...", model="glm-4.6")
agent.send("Привет!")            # → строка ответа (вся память внутри агента)
for ev in agent.send_stream(...) # → события {'event': 'delta'|'done'|'error', ...}
agent.reset()                    # забыть диалог, личность остаётся
agent.configure(name=..., model=..., system_prompt=...)  # перенастройка на живом агенте
agent.describe()                 # снимок: имя, модель, промпт, реплики, история
```

Память: пара user/assistant дописывается в историю только когда ответ дошёл
до конца — если клиент отключился посреди генерации, «повисший» вопрос в
память не попадает. Хранятся последние 20 реплик (старые вытесняются).
Пустой системный промпт = промпт по умолчанию, собранный из имени агента.

## Память диалога

История хранится **в экземпляре агента на сервере**, а не в браузере: можно
перезагрузить страницу — клик по чату в сайдбаре восстанавливает диалог
запросом `GET /api/agent`, вместе с метаданными каждого ответа (модель,
токены, латентность хранятся в самом агенте рядом с репликой). Кнопка
«сбросить диалог» вызывает `agent.reset()` на сервере. Память агентов живёт
до перезапуска сервера; одновременно удерживается до 16 агентов (LRU).
Под каждым ответом — метаданные: модель, `finish_reason`, токены, число
реплик в памяти, латентность.

## Запуск

Фронтенд собран и закоммичен в `day6/frontend/dist/`, поэтому Node не нужен:

```bash
cp .env.example .env   # вписать GLM_API_KEY и/или DEEPSEEK_API_KEY
.venv/bin/python day6/server.py
```

Открыть <http://127.0.0.1:7865> (в WSL2 — по eth0-IP: `0.0.0.0` уже
прописан). Ключи — из `.env` в корне репозитория, у агента два провайдера
(оба совместимы с OpenAI SDK): Z.ai (`GLM_API_KEY`) и DeepSeek
(`DEEPSEEK_API_KEY`, `https://api.deepseek.com/v1`). Модели:
`deepseek-v4-flash` (по умолчанию) и `deepseek-v4-pro` — рассуждают сами
(native); `glm-4.6` (thinking off) и `glm-5.3` (effort low) — нужны средства
на балансе Z.ai. Клиент подбирается по провайдеру модели, поэтому агентов
на разных провайдерах можно свободно перемешивать; без нужного ключа в
`.env` выбор такой модели вернёт понятную ошибку, а не упадёт.

Маршруты: `/` — чат; `GET /api/agent?session_id=` — память агента;
`POST /api/chat {session_id, message, config?}` — диалог (NDJSON:
`start` → `delta`… → `done`); `POST /api/reset`, `POST /api/forget` —
очистить память / удалить агента сессии. Пока агент отвечает, повторный
запрос к его сессии — 409; другие сессии не ждут.

## Пересборка фронтенда

```bash
cd day6/frontend
npm install        # один раз
npm run build      # dist/ для сервера
npm run dev        # режим разработки: :5177, прокси /api → :7865
```
